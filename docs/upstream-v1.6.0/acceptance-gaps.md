## Other behavior gaps
- **Malformed after-run reports:** native typed hook results cannot represent the upstream string-valued task list. The native aggregate also uses a generic unsupported-JSON diagnostic for a function payload. The valid owned child and exact hook cause are verified separately.
- **Failed-run withdrawal:** upstream withdraws the queue in one commit. Go does the same within its write limit, but a lower configured limit can reject the whole commit. Any fix must preserve atomic withdrawal and enforcement of the limit; any retained difference needs explicit acceptance.
- **JavaScript event and value identity:** the upstream process observes `unhandledRejection`, some tests compare object or SDK identity, and the Mistral tests verify removal of JavaScript symbol keys. Go checks its own cancellation, callback and result behavior. These checks do not establish JavaScript event or object identity; classify the required equivalent before closing those rows.
- **Codemode replay:** Go rejects unsupported saved-start shapes in storage before replay. The source version test rewrites its saved start and expects a tool-result refusal. Go still joins late host callbacks before returning the result. At capacity one, matching the source's earlier submission settlement would require an explicit cleanup scope outside invocation and dependency accounting. No such exception is enabled. New runs on the built-in positioned worker meet the pinned 50-result publication limit. Saved runs keep their original journal policy. That comparison does not close unsupported saved-start shapes or the delayed callback join difference. See [batching requirements](codemode-batching.md).
- **Codemode store limits:** the five-value patch now fits in bounded records under the default SQLite limits. A tighter frame or write-count limit can still refuse the whole update. The native limits stay in force; there is no partial application.
- **Codemode source size:** the published sandbox accepts the pinned large image literal. Native QuickJS preserves its 1 MiB source setup limit and refuses that literal before output. A smaller program emits the same image bytes; that checks output, not admission of the original source.
- **Standalone Schema setup:** `CompileJSONSchema` now rejects reachable unresolved references during preparation by default, with a value-level reject option. The older checks and tool validation retain lazy resolution. The prepared API now supports JSON-value coercion and parsing; full meta-schema checks and broader JavaScript-specific behavior remain open.
- **Codex raw mid-conversation reasoning:** the pinned raw unset-effort call sends only the off effort, without a configuration item or provider marker. Go retains the simple-options configured default for that model. The nonconfigured fallback no longer adds a summary. Generic `Complete` currently reaches the same raw callback when reasoning is unset, so changing only that callback would also change the generic default. Decide whether to preserve the generic default while splitting direct request modes, or change the generic default to raw.
- **Anthropic thread metadata:** on the cold request with thinking disabled, the beta header now matches. The SDK still adds `?beta=true` and exposes hook-only `betas`; Go uses the queryless path and sends some historical user text as a block array rather than a string. The comparisons keep those remaining differences separate.

Continue the offline case mapping and narrower runtime checks without waiting for these approvals. Do not silently exclude a case or use one run to stand for a different host or interface.
