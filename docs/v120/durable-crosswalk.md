## Inline format policy

`TestRead120InlineFormatsAndExactBudgets` covers PNG/JPEG/GIF/WebP byte preservation, exact dimension/base64 limits, one-unit-over-budget rejection and cancellation. `TestRead120InlineRejectsTruncatedImageHeaders` records native decoder validation for incomplete PNG/GIF/WebP/JPEG headers. Focused race count3 passed1.019s; the full read/image120 race selection passed12.352s, plus tools vet. These are test-only additions; production remains at the full-root race receipt below. Native decoder validity, input/pixel budgets and Go encoding policy remain in force; upstream permissive malformed headers are not a reason to weaken them.

## Error-result image regression

`TestTool120ErrorResultRetainsLargeImageTranscript` now checks ordinary model tools returning `IsError` with an image larger than the journal string limit: the provider receives the error flag and image, a reopened conversation retains the image, and a second generation does not execute the tool again. Memory and journal cases pass under race three times (9.307s). The combined error-image/transcript/reference-integrity selection passes under race (15.366s), plus durable vet. Production behaviour is unchanged from the integrated race receipt below.

Thrown executor errors discard returned result blocks and use retained progress/error diagnostics; they do not share the returned-error-result contract. An initial probe incorrectly assumed otherwise. A subsequent fixture used concatenated padded base64, correctly rejected by image validation; replacing it with one valid base64 encoding produced the regression above. Neither probe justified a production relaxation.
