# Typed model equality

At upstream `f9a26365568127461c47a07a37dcb42c140a3ac5`, `packages/ai/src/models.ts:modelsAreEqual` compares `getModelType`, provider and ID. `packages/ai/test/model-types.test.ts:68–73` checks that an omitted type defaults to chat and equals explicit chat, but an image model with the same provider and ID does not. At parent `4887b43`, native `ModelsAreEqual` compared only provider and ID, so the new `TestMainModelsAreEqualHonoursType` failed on the different-type control. The helper now uses existing `GetModelType` as well as provider and ID; nil, provider, ID and legacy-chat controls pass. This affects callers comparing `*Model` values carrying different explicit `Type` fields.

The native public helper accepts only `*Model`; representing the image type inside that struct is an adaptation. It does **not** implement or prove upstream's cross-struct `*ImageModel`/`*ClassifierModel` equality API. Native typed lookup and legacy equality controls, related thinking tests, cost-overflow controls, `go vet . ./tests`, formatting and `git diff --check` passed with `CGO_ENABLED=0`. An overlay restoring the parent helper failed the type control. Scratch was removed; broader model type, catalogue and full parity remain open.
