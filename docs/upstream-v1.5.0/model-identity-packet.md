# Typed model equality

At upstream `f9a26365568127461c47a07a37dcb42c140a3ac5`, `packages/ai/src/models.ts:modelsAreEqual` compares `getModelType`, provider and ID. `packages/ai/test/model-types.test.ts:68–73` checks that an omitted type defaults to chat and equals explicit chat, but an image model with the same provider and ID does not. At parent `4887b43`, native `ModelsAreEqual` compared only provider and ID, so the new `TestMainModelsAreEqualHonoursType` failed on the different-type control. The helper now uses existing `GetModelType` as well as provider and ID; nil, provider, ID and legacy-chat controls pass. This affects callers comparing `*Model` values carrying different explicit `Type` fields.

The native public helper accepts only `*Model`; representing the image type inside that struct is an adaptation. It does **not** implement or prove upstream's cross-struct `*ImageModel`/`*ClassifierModel` equality API. Native typed lookup and legacy equality controls, related thinking tests, cost-overflow controls, `go vet . ./tests`, formatting and `git diff --check` passed with `CGO_ENABLED=0`. An overlay restoring the parent helper failed the type control. Scratch was removed; broader model type, catalogue and full parity remain open.

At parent `d2bd8e5`, `GetSupportedThinkingLevels` returned `[off]` even when a reasoning model explicitly disabled every level, including `off`. Pinned `models.ts:getSupportedThinkingLevels` filters all disabled entries; an isolated Bun probe of the exact source functions returns `[]`, while `clampThinkingLevel(high)` separately falls back to `off`. The new `TestMainThinkingAllLevelsDisabled` failed at baseline and now passes with that distinction, a disabled mapping control and a non-reasoning `[off]` control. This changes the public supported-level list for the all-disabled configuration; clamping and the nil mapping rejection are unchanged. Focused thinking tests and provider reasoning tests for Anthropic, Bedrock, OpenAI Responses and Google passed count1; the parent overlay reproduced the failure. `go vet` on those packages plus root/tests, formatting and `git diff --check` passed; scratch was removed. This source-derived edge case does not establish full model/catalogue parity.

At parent `4698aea`, the unchanged `ModelsAreEqual(*Model, *Model)` signature could not compare actual `*ImageModel` or `*ClassifierModel` values, so source `model-types.test.ts:72–73` was only represented by an adapted `*Model`. Added a separate `TypedModelsAreEqual(any, any)` helper without changing the existing function signature. It compares effective type/provider/ID for values and pointers of the three native model structs; nil pointers and unsupported values return false. `TestMainTypedModelsAreEqual` covers actual cross-type identity, same-type equality, explicit and default types, nil, value forms and different IDs/providers. The baseline had no such API, and a type-removal overlay fails the cross-type control. This Go helper is an API adaptation, not proof for arbitrary JavaScript objects.

Rechecked the official v1.5.0 npm archive against its recorded SHA-256 and ran the independent full-record comparator: **1592 chat, 64 image, 56 classifier, all 1712 records match**. Only those stale count assertions and messages were updated; existing representative metadata and catalogue-delta assertions remain intact and pass. Seven focused typed equality, lookup, catalogue, legacy and thinking controls pass count1; `go vet . ./tests`, formatting and `git diff --check` pass. Archive, extracted data, overlays and temporary measurement script were deleted. Catalogue comparator and bounded tests are not full-SDK acceptance.
