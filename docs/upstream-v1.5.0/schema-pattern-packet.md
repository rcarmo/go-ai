# Schema string patterns

`ValidateToolArguments` accepts a string that violates a pinned `pattern`. At upstream `f9a26365568127461c47a07a37dcb42c140a3ac5`, `packages/ai/test/validation-probes.test.ts:104–106,488–489` accepts `äb` and rejects `p{L}` for `^\p{L}+$`. At local `80a1bd6`, `TestMainValidationStringPatternUnicodeProperty` accepted both. The existing pinned-shape optional-null tests for declared, additional and pattern properties passed in the same run (0.012s). The failing oracle is retained outside the default build at `tests/testdata/upstream-main/pending/validation_string_pattern_test.go`; the native fixture represents the TypeBox object as JSON.

The same upstream test file expects lookbehind `(?<!x)y` to accept `y`, and invalid `[` to throw during schema compilation (`:235–242,527–528`). Those outcomes have not been ported or run in this packet. Upstream `validation.ts` caches a compiled TypeBox validator per schema object and formats issue paths. Native `context.go:schemaAcceptsValue` currently checks types, numeric bounds and formats but does not check the string `pattern` keyword. `schema_validation.go:issue` therefore also lacks a pattern-specific diagnostic. `patternProperties` normalization and member traversal separately use Go RE2; unsupported patterns cause conservative additional-property handling. These are distinct gaps.

`internal/quickjs/regexp.go:CheckRegExp` checks Unicode-mode syntax in a bounded isolated WASM instance; it does not match values. Matching must not interpolate pattern or input as code. A proposed implementation should add a bounded ECMAScript Unicode-mode match primitive, return a distinct invalid-pattern result and infrastructure/timeout error, memoise within one validation call without approximate keys, and apply it consistently to membership, union selection and diagnostic generation. Match deadline and memory limits must protect callers from adversarial patterns. Before using the primitive for `patternProperties`, establish semantics for overlapping patterns, additional properties, normalization order, resource exhaustion and invalid schema compilation. Do not equate Go regexp syntax with the pinned JavaScript contract.

Acceptance needs the unchanged positive/negative Unicode fixture, source-shaped lookbehind and invalid-pattern controls, astral and class controls, ordinary non-matching strings, nested/union and optional-null regressions, infrastructure failure and bounded pathological-regex controls, plus input ownership checks. Invalid schema handling currently has separate native compatibility behaviours; preserve the pinned throw assertion and examine caller impact before implementation. This packet did not run full validation, alter runtime code, lift the `multipleOf` pause or establish pattern parity.
