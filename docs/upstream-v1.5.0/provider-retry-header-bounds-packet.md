# Provider retry server-delay bounds

The pinned `packages/ai/src/utils/provider-retry.ts:40–65` validates a finite server-requested delay against the configured cap before sleeping. At parent `ed47ced`, a `retry-after` or `retry-after-ms` value of `1e100` converted to a negative Go duration before validation. Both headers bypassed the default cap; the production retry loop made a second request immediately.

Numeric header values are now checked against the cap before conversion to `time.Duration`. Out-of-range values saturate at the Go duration bounds when the cap is disabled or the value is negative. This is a Go representation adaptation: JavaScript can represent a wider finite delay, while Go cannot. Negative durations still reach the existing zero-delay sleep clamp. The existing HTTP-date path retains duration precision and uses overflow-safe error formatting.

`TestMainProviderRetryServerDelayBounds` passed seven cases covering both headers, the default cap, disabled cap, negative saturation, fractional milliseconds and the cap boundary. `TestMainProviderRetryHugeServerDelayStopsBeforeRetry` passed through the public retry loop. Both tests are source-derived; they are not ports of upstream tests. The two fallback controls also passed (`make test PACKAGES=. TEST_FLAGS="-v -run 'TestMainProviderRetry(ServerDelayBounds|HugeServerDelay|Fallback)' -count=1 -timeout=45s"`, 0.005s). Six existing provider controls passed after the change (count1). An overlay restoring the parent implementation failed the production-path control with two requests. `go vet . ./tests`, formatting and `git diff --check` passed with `CGO_ENABLED=0`; overlay scratch was removed.

JavaScript `Number.parseFloat` accepts numeric prefixes that Go's `strconv.ParseFloat` rejects; this remains open. Extremely large seconds whose multiplication by 1000 becomes JavaScript infinity, date parsing differences, nanosecond rounding, cancellation of saturated timers and provider-specific status wiring need separate examination. Full provider retry parity, the full suite, profiling, hosted CI and release remain unverified.
