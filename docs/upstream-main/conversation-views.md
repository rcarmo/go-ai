# Conversation views and transcript windows

`ConversationHandle.View` and `Watch` now expose transcript history with independent windows. Model-context APIs and legacy event snapshots retain their active-head entries and receipt pairing. The target is upstream `81f3cd412758ebdd92324c7d63b669a189408d0a`.


## Pending conversation operations — development checkpoint

Exact-native conversation watches now fold contiguous pending successful projections off the Session line before each callback. Delayed Start and blocked listeners receive the latest pending value/context with Chord leaf, append, structural-barrier and root rules. An active callback keeps its own delivery. Every selected publication must release its readiness fence. Consumed projection slots clear before delivery.

The source is `packages/chord/src/watch.ts` and `delta/pending.ts` at the pinned revision: `ConversationViews` uses the JSON watch. Its queue does not have the native-value watch’s 100-frame reset. Raw commit subscriptions and authoritative adapter frames retain that existing reset and their individual delivery path. Projection errors remain separate delivery boundaries.

Native limits remain unchanged. Folding keeps independent value/operation DTO budgets, validates replay from the last delivered view, and falls back to a bounded latest-value root for operation/member/node/byte or intermediate-value overflow. A merged append can move bytes ahead of a later freeing set; replay validation catches that transient overflow. Source permits 10,000 folded operations; native permits 4,096. Tests cover 4,096/4,097, byte-bounded recovery, a rejected undersized root, independent node budgets and the transient append case. Source equivalence above native bounds remains open. Pre-fold frame storage still uses the existing byte quota and can reset before folding could shrink it; incremental pending storage/work bounds remain open.

`durable/view_pending_main_test.go` covers delayed/blocked delivery, 102 same-path edits, latest uncancelled context, off-line re-entry, replay, detached values/operations and a successor edit across memory/journal/SQLite. `durable/view_pending_bounds_main_test.go` adds distinct readiness fences and native resource controls. Earlier 105-publication transcript tests now assert folded publication-time windows without a count-only reset; structural document replacements retain all 105 operations. Existing byte-overflow root, adapter, failure/Close, receipt, consumed-slot and definition-watch checks remain active. Shared leaf-folding logic serves both JSON watch kinds.

Focused normal checks pass three repetitions, shuffle 42, CGO 0/1 (34.200s/60.093s). Focused race checks pass three repetitions (183.081s), with the named high-node control separately once across all backends (67.473s). Durable vet and staticcheck v0.8.2 pass in both CGO modes. Five mutations are rejected: no fold (6 backend leaves), count-only reset (6), last-ready-only (3), omitted transient replay (1), and joint DTO budget (1). An initial readiness probe accidentally modified the earlier definition-watch loop and passed; a unique conversation-loop anchor corrected the probe, then all three affected backends rejected it. Mutation files and logs were removed after analysis.

These are focused development checks. No new full-suite/full durable race, performance or pre-release acceptance claim. Adapter window parity, bounded hydration, shared references/GC, synchronous observers and full semantic convergence remain open. The sections below retain earlier checkpoint evidence.

## Document-operation checkpoint

Exact-native conversation frames now follow `packages/durable/src/harness/view.ts:340–352`. A mounted document retains its ID/version alongside the publication-time window. Matching incarnations forward the published operation log under `docs/kind`; a document root replacement becomes a set at that path. Changed IDs or versions emit whole-document sets even when the value is unchanged. Retirement removes only the mounted ID. Document operations precede entry append/trim/before operations.

Acquisition seeds these small ID/version maps from the admitted snapshot. Preparation copies them; receipted adoption installs the new map with the new head. Abandoned preparation leaves both unchanged. Each watch owns its operation payloads and paths, and callback mutation cannot alter another watch or the private head. Adapter/raw subscriptions retain their previous projection paths.

Native operation and intermediate-view limits still apply. Prefixed document operations can temporarily exceed the full-view budget despite a small final value. Delivery then uses the existing bounded final-value diff, which can be empty for a net-zero change. Even an empty fallback adopts the receipted incarnation map; it consumes no callback slot or queue bytes. The following edit can therefore use the current incarnation. Source tuple equivalence outside those bounds needs a disposition; limits have not been widened.

`durable/view_document_ops_main_test.go` covers replacements with entries, explicit net-zero edits, equal-value recreation/version changes, retirement, peer ownership, abandoned preparation and empty bounded-diff witness adoption across memory/journal/SQLite. A real earlier-ID reservation places replacement creation before old-incarnation retirement in publication order; the old retirement is ignored, and the following edit uses the new incarnation. The initial recreation fixture incorrectly reused `builtin()` after retirement; that helper reads the committed baseline. Explicit `CreateDocument` exercises the intended lifetime without changing the helper.

Final focused document/transcript/view/provider/observation/task-graph normal checks pass three repetitions with shuffle 42 in CGO 0/1 (29.685s/50.733s). Focused race checks pass three repetitions (109.259s), with the high-node DTO control separately once across all backends (67.405s). Durable vet and staticcheck v0.8.2 pass in both modes; the protected prototype is temporarily path-stashed for staticcheck and restored unchanged. Seven mutations are rejected: final-value document diffs (12 backend leaves), ignored retirement ID (3), premature incarnation adoption (3), borrowed callback operations (3), skipped document transient validation (1), discarded empty-diff witnesses (3), and queued empty-diff callbacks (3). Mutation sources/logs are removed after analysis. Full-suite, full durable race, performance and pre-release acceptance checks have not run for this checkpoint.

## Entry-operation checkpoint

Exact-native publication frames now follow `packages/durable/src/harness/view.ts:364–371`: append **all** entries in the publication, splice away the oldest entries when the window exceeds `max`, then set `before`. Entries discarded immediately by that trim still appear in the append tuple. A final-value diff could reconstruct the same view while omitting those entries and emitting `before` first; it no longer substitutes for this representable entry sequence. Mounted-document operations used native diffs in the `5dd73d1` entry checkpoint.

Native intermediate-document and operation limits are unchanged. A transient append may exceed member or document-byte limits even though the trimmed result fits; the entire inserted batch can also exceed the operation record budget. In these cases delivery retains the existing bounded final-value diff. This is a documented limit of source tuple equivalence, not acceptance of a retained divergence or permission to widen those limits. Raw subscriptions, adapter delivery and the existing overflow reset are unchanged.

`durable/view_window_ops_main_test.go` checks growth, equal bounds and one-entry windows across memory/journal/SQLite. Expected tuples use independently read committed entries, including sequence/position fields and entries immediately dropped. Every operation batch replays the preceding view; predecessor IDs are checked independently. Three additional controls exercise native member, intermediate-byte and inserted-record-byte limits. A document-diff overflow control preserves the complete view envelope: a root produced from the document-only projection must not discard `entries` or `before`.

## Publication-time window checkpoint (`fa933f5`)

Exact-native conversation watches now advance a private window once per adopted publication. Acquisition builds and attaches the projection on the same Session line. Preparation computes detached normal/root frames without mutating the head; only receipted enqueue installs it. An abandoned preparation cannot change later windows. Native `Value()` retains its existing last-delivered meaning; callbacks and value copies stay off the mutation line.

Overflow now replaces the backlog with the prepared publication-time window, including its exact `Before`, then delivers subsequent frames in order. It no longer reloads the newest `min` from a full-history snapshot. Conversation frames retain projected windows instead of full-history fallback snapshots. Ordinary commit subscriptions and task-graph frames keep their existing raw publication/resnapshot contracts. Baseline hydration still reads an admitted snapshot.

Adapter authority requires an explicit exact-native witness. A wrapper present at acquisition, or admitted later, retains the old raw publication/resnapshot path. Six development guard failures exposed stale provider projections at overflow; both installation times now honour adapter data. Once a wrapper publication invalidates a watch's head, restoring the native store cannot re-enable that stale head; a fresh watch can acquire a new witness. No wrapper field is inferred authoritative from equal sequence/IDs. Publication-time window preservation for adapters is still open.

The fixed observer reservation charges both each retained value and its operations. Byte/count overflow uses a root projection within that same reservation. Value and operation DTOs retain their independent node/depth/size checks; a joint validation envelope wrongly rejected a legal 100-entry/60,000-item append during development and was removed. Root tuple accounting adds its eight-byte JSON wrapper to the validated value. Consumed queue slots are cleared before callbacks so the backing array releases owned projections and contexts.

Projection errors are queued listener diagnostics, never transaction failures. They do not install a head; later projection work stops until that watch ends. Delivery/reporting waits for readiness and listener Start. Reports can re-enter committed reads. Stop, acquisition cancellation, Close and first fatal failure suppress prepared callbacks; producer cancellation after storage does not cancel an adopted frame. No observer callback runs during preparation or publication.

`durable/view_publication_main_test.go` adds six initially failing overflow leaves: 105 appends, an empty future-cursor window, and either delayed Start or a blocked callback, across memory/journal/SQLite. Every delivered window and predecessor is checked against an independent append/trim sequence, and operations replay each revision. Additional controls cover abandoned preparation, off-line/reentrant local failure with a healthy peer, byte-triggered replacement, consumed backing slots, independent DTO budgets, readiness, cancellation and endings. The source-derived overflow probe targets the native boundary; source's 6,000-publication/10,000-operation scenario is still unported.

Focused normal checks pass three repetitions with shuffle 42 in CGO 0 and 1, covering transcript/view/provider/legacy-event, observation/subscription, task-graph and prepared-publication regressions. Durable vet and staticcheck v0.8.2 pass in both modes. Staticcheck initially flags ST1008 in the protected untracked continuation prototype; temporarily path-stashing only that excluded file allows the complete shipped package/test check, after which source integrity and restoration are verified. A GOFLAGS overlay did not exclude it from staticcheck's source analysis; no ignores or prototype changes were added.

Focused race checks pass three repetitions with shuffle 42 except the high-node DTO control, which passes separately once across all three backends. The original combined three-repetition run hit its 240s package deadline while that control was running. Partitioned commands cover the entire focused set without changing deadlines or assertions; no full durable race result is established. Premature head mutation, operations-only byte accounting, retained consumed-slot and ignored native-witness overlays each fail all three backend controls. Disposable overlays and the timed-out journal fixture are removed after diagnosis; no profiles were captured.

## Transcript-window checkpoint (`d3fa961`)

Both methods accept one optional `ConversationWindow`. Its pointer fields distinguish omitted `Min`/`Max` from explicit invalid zero. Defaults are `min=50`, `max=2*min`; positive bounds must be safe integers with `max >= min`. Native DTO limits continue to apply to actual values. A large declared window can hydrate a short transcript without allocating its declared capacity. `From` is an inclusive entry ID used only at acquisition; later publications append even when their IDs are below that initial cursor. The resolved scalar bounds are detached from caller pointers.

Initial hydration selects entries from `From` when that selection has at most `max` entries; otherwise it selects the newest `min`. Without `From`, it selects the newest `min`. `Before` identifies the actual preceding visible entry, including allocator gaps, and is omitted at transcript beginning. A future `From` starts empty with the latest existing entry as its predecessor. Fork hydration honours inherited cutoffs.

Live publications append their entries in ID order. Summary/reset markers stay in the transcript. Windows grow to `max`; a publication exceeding it drops the oldest entries down to `min` and advances `Before`. Each watch owns its bounds and detached values. Trimming allocates a retained slice so dropped entries are not kept through its backing array. Model-context head selection is unchanged. `conversationSnapshot` explicitly uses the active-head helper to preserve legacy event receipt pairing.

## Provider projection checkpoint (`56073ba`)

Native conversation views now include the singleton `pi.provider` document when it exists, matching the mounted built-in set in upstream `81f3cd412758ebdd92324c7d63b669a189408d0a`, `packages/durable/src/harness/view.ts` and `packages/durable/test/harness-view.test.ts`.

`mountedKind` had omitted it while admitting `pi.agent`, `pi.live`, `pi.inbox` and `pi.usage`. The shared filter now covers provider documents in initial `View`/watch hydration, live publications and overflow resnapshots. Retirement removes the mounted document. An absent provider document is not created by reading a view. Provider identity generation, persistence, requests, fork policy and credentials are unchanged.

Focused tests also found a replay defect for empty views. `buildConversationView` retained a nil entry slice, so overflow operations replaced the root with `entries: null`; `copyConversationView` exposed the same callback value as `entries: []`. Empty views now consistently expose an array, and root operations reproduce the detached callback value.

## Remaining view work

Source pending-operation folding, overflow thresholds and tuple equivalence outside native operation/intermediate-value bounds remain open. Native conversation delivery still uses its 100-frame/byte-bound queue; source folds pending operations and replaces past 10,000 operations. A delayed native consumer can receive several frames where source sends one folded revision. Exact-native publications retain mounted document intent and entry append/trim/before tuples within native intermediate/operation limits; bounded fallback cases and adapter delivery still use final-value diffs. Publication-time window contents and predecessors survive the exact-native overflow boundary. Adapter watches retain authoritative raw resnapshots and can still reload only `min` at overflow; their source window-state/work-bound alignment is open.

Hydration currently derives visible history from the admitted snapshot; source uses bounded storage scans. Bounded scan/work parity, shared mounts/documents, reference identity and long-lived collection tests are open. Existing detached native values do not establish source shared-reference identity. Full `ConversationTranscript` gap/load/resume semantics and synchronous observers also need implementation/review.

Synchronous observers remain a separate [publication-contract gap](synchronous-observers.md). Both source test inventories remain explicitly partial.
