## Durable conversation lifecycle ports

`durable/view_lifecycle_oracle_main_test.go` adds two scenarios from `packages/durable/test/harness-view.test.ts:330–380`, through unchanged production code on all three backends:

- `TestMainViewUpstreamListenerIsolation`: start two watches, update `pi.live.text` to `x`, observe the first listener's `listener failed` error and `listener_error` closure, then update to `y`; the other watch receives both frames and stays open. The source's shared-docs reference-identity assertion is unported. Native detached ownership supplies no equivalent assertion.
- `TestMainViewUpstreamAtomicPublication`: append note data `1` and `2` and set `pi.live.text` to `done` in one commit; receive one frame, verify its two IDs, replay operations and compare with a newly acquired watch. Editing unmounted `test.view.extra.x` to `1` creates no pending/delivered frame or value change. Native entries require the empty `Value` envelope and minted IDs. The native setup initialises built-ins without executing the source's provider/chat setup.

The source's event-loop drain maps to awaiting the corresponding delivery. No extra gate changes which commits enter a batch; the no-frame assertion checks the admitted queue directly without a sleep.

Ten normal repetitions/shuffle 42 pass in CGO 0/1 (0.473s/0.893s), five race repetitions/shuffle 7 pass (1.906s), and combined lifecycle/hydration oracles pass three race repetitions/shuffle 42 (3.936s). Durable vet/staticcheck v0.8.2 in both modes and module verification pass. ## Failure calls and retained frame contexts

Source tests at 394–510 keep recoverable failures open, fold pending values/failures to the newest call, retain the previous delivered value and force a root replacement on recovery. These generic Chord assertions are unported. A producer audit at the pinned revision found no `.fail()` or failed-call delivery in `packages/durable/src/harness/view.ts` or `packages/durable/src/session/session.ts`: the view constructs Watch, forwards values/terminal ends and reports observer faults through `guardObserver`. The Session's `failed` end states are terminal failures, not recoverable calls.

Native `ConversationWatch.Start` terminates on a local projection error, while `DocumentWatch.StartFrame` lacks a failed-call payload. Native quota rejections are outside the source's unbounded input domain and are not a demonstrated durable producer mismatch. No quota-error reinterpretation or sticky-failure change was made. Next: identify a real source producer that exercises recoverable computation failure before implementing a native tagged failure surface; preserve legacy error handling, adapter authority, DTO budgets and readiness/Close fences.

Source tests at 631 and 666 require a plain call object with no context, and collection of producer payloads even when consumers retain calls. Native `WatchFrame` exports `Context` as well as receiving the callback context separately. Retaining that frame can retain producer context values. Existing detached-value and consumed-slot tests do not establish the source lifetime assertion. A temporary Go weak-reference probe confirmed the gap: a pointerful 1 KiB producer payload survived five GCs while a delivered/stopped native frame was retained. Clearing only that retained frame's Context released the payload within five GCs in ten repeated control runs (0.027s), with the frame kept alive. This is a targeted reachability check on Go 1.27.3, not a memory benchmark or a general eventual-GC guarantee. The probe and overlay were removed immediately after analysis. Next: evaluate a context-free tagged delivery representation alongside the legacy API; removing or clearing the existing public context field needs a compatibility disposition. Source GC and shared-identity parity remain open.

## Development checks

Go 1.27.3, GOMAXPROCS=4: new scenarios pass ten normal repetitions/shuffle 42 in CGO 0/1 (0.432s/1.213s), five race repetitions/shuffle 7 (2.093s), and durable vet/staticcheck v0.8.2 in both modes. The new scenarios with existing pending-delivery and close/cancellation regressions pass three race repetitions/shuffle 42 (41.720s); module verification passes. Initial setup probes omitted a required checkpoint predicate, a helper's limits argument and JSON number/map normalisation; those were test errors, not runtime failures.

Six original upstream test bodies (the two value cases and four lifecycle cases through listener failure, excluding abort) also passed against the pinned Watch implementation under Bun with a small synchronous Vitest assertion adapter. This was a selected-body run, not full Vitest. The original source end/failure body ran there but has no exact native port.

Two production overlays prove the native assertions reject regressions: keeping only the newest pending frame fails all six value leaves; overwriting an existing terminal cause fails all three listener-error leaves. Overlays, temporary source extracts, assertion runner and logs were removed after analysis. Full-suite, full race and acceptance profiling were not run for this checkpoint.
